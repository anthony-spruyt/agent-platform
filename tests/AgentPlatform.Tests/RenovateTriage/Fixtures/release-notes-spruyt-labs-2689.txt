### [`vertical-pod-autoscaler-1.7.0`](https://redirect.github.com/kubernetes/autoscaler/releases/tag/vertical-pod-autoscaler-1.7.0)

[Compare Source](https://redirect.github.com/kubernetes/autoscaler/compare/vertical-pod-autoscaler-1.6.0...vertical-pod-autoscaler-1.7.0)

#### Changes by Kind

##### API Change

- Added MemoryAggregationIntervalSeconds for the VPA object ([#&#8203;9317](https://redirect.github.com/kubernetes/autoscaler/pull/9317), [@&#8203;omerap12](https://redirect.github.com/omerap12))
- EvictAfterOOMThreshold is now per vpa ([#&#8203;9071](https://redirect.github.com/kubernetes/autoscaler/pull/9071), [@&#8203;omerap12](https://redirect.github.com/omerap12))
- The VPA support InPlace update mode. VPA will not evict any pods and only try to resize pods inplace. ([#&#8203;8888](https://redirect.github.com/kubernetes/autoscaler/pull/8888), [@&#8203;omerap12](https://redirect.github.com/omerap12))
- Users can configure a startupBoost policy in the VPA spec. ([#&#8203;9141](https://redirect.github.com/kubernetes/autoscaler/pull/9141), [@&#8203;kamarabbas99](https://redirect.github.com/kamarabbas99))
- VPA now stores a observedGeneration in both status and condition fields. ([#&#8203;9524](https://redirect.github.com/kubernetes/autoscaler/pull/9524), [@&#8203;adrianmoisey](https://redirect.github.com/adrianmoisey))

##### Bug or Regression

- Fix bug where VPA admission-controller could write a webhook with an empty cert for a brief period. ([#&#8203;9599](https://redirect.github.com/kubernetes/autoscaler/pull/9599), [@&#8203;adrianmoisey](https://redirect.github.com/adrianmoisey))
- Fixed OOM detection for pods with `restartPolicy: Never` ([#&#8203;7955](https://redirect.github.com/kubernetes/autoscaler/pull/7955), [@&#8203;tkukushkin](https://redirect.github.com/tkukushkin))
- Fixed a bug where the presence of a LimitRange object with CPU constraints in the cluster prevented VPA from recreating Pods managed by the targeted controllers. The updated code section, which proportionally reduces resource requests and limits, could result in the loss of sub-millicore values. ([#&#8203;8946](https://redirect.github.com/kubernetes/autoscaler/pull/8946), [@&#8203;iamzili](https://redirect.github.com/iamzili))
- Fixed a bug where users could use alpha (off-by-default) features by updating an existing VPA resource, bypassing the feature gate check. ([#&#8203;9557](https://redirect.github.com/kubernetes/autoscaler/pull/9557), [@&#8203;adrianmoisey](https://redirect.github.com/adrianmoisey))

##### Other (Cleanup or Flake)

- Bump Kubernetes dependencies to 1.36.0 ([#&#8203;9547](https://redirect.github.com/kubernetes/autoscaler/pull/9547), [@&#8203;adrianmoisey](https://redirect.github.com/adrianmoisey))
- Reduce VPA memory usage by stripping away unnecessary managed fields from informer cache ([#&#8203;9634](https://redirect.github.com/kubernetes/autoscaler/pull/9634), [@&#8203;adrianmoisey](https://redirect.github.com/adrianmoisey))
- Update flag in-place-skip-disruption-budget is now beta ([#&#8203;9655](https://redirect.github.com/kubernetes/autoscaler/pull/9655), [@&#8203;omerap12](https://redirect.github.com/omerap12))
- Improved VPA validation error messages now pinpoint exactly which fields are invalid, making it faster to diagnose and resolve configuration issues in your VerticalPodAutoscaler specs. ([#&#8203;9591](https://redirect.github.com/kubernetes/autoscaler/pull/9591), [@&#8203;adrianmoisey](https://redirect.github.com/adrianmoisey))
